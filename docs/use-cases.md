# 使用场景 · Use Cases

8 个真实场景的对话脚本，看一眼就知道这 skill 在你的工作流里能怎么帮上忙。

> **English summary**: 8 realistic dialogues showing how the Feishu Aily agent assists animation production teams: daily progress check, deadline chasing, new member onboarding, project archival, rework flow, mid-project schedule adjustment, weekly digest, recovering from a mis-clicked change.

## 场景 1：早会查看完成度

**角色**：制片人，每天 9:30 开晨会前看一眼进度。

```
你：早上好，现在完成度多少？
它：早上好。
    【完成度】项目《海岸线》
    加权 68.4% / 平均 72.1% / 差额 -3.7%（剩下的偏难）
    按难度：S 62.5% · A 80% · B 88% · C 100%
    DDL 还有 7 个工作日。
    要看阶段分布或谁负载高吗？

你：看下负载
它：在手任务前 3 名：
    - 张三（原画 S/A）8 张进行中
    - 李四（清线）5 张进行中
    - 王五（上色）3 张进行中
    其他人都在 2 张以内。
```

**关键能力**：加权 vs 平均完成度对比、按维度切片、报告短而平不焦虑。

## 场景 2：催稿（不打扰团队）

**角色**：制片人，发现今天有人延期了。

```
你：今天有谁延期了？
它：3 张过截止了：
    - S1C008 角色原画（张三）5/15 截止，过了 2 天
    - S1C012 清线（李四）5/16 截止，过了 1 天
    - S1C015 上色（王五）5/16 截止，过了 1 天
    我私信了三位，问要不要更新时间。要在群里同步吗？

你：先不发群，看他们怎么回
它：好。回了就告诉你。
```

**关键能力**：默认私信不发群、催交语气温和（"要不要更新时间"而不是"请尽快"）、用户决定才升级。

## 场景 3：新人入职 + 自动分配

**角色**：制片人，新招了个清线师。

```
你：小明加入了，做清线，能接 A 卡和以下，并发 2
它：已在"团队配置"加上：
    小明 / 飞书人员（待你补 ID）/ 职能=清线 / 卡级=A,B,C / 并发=2
    现在还有 5 张清线没分配，要给他派吗？

你：派吧
它：【分配预览】
    小明 → S1C003、S1C007、S1C012（A 卡）
    王二（已有清线 3 张）→ S1C018、S1C023（B 卡）
    回「确认」我就落表。

你：确认
它：好。已发私信通知小明（5 张接手镜头 + 截止日期）。
```

**关键能力**：团队配置自动建表、分配按职能 + 卡级筛选 + 负载均衡、强制 dry-run 预览。

## 场景 4：返修流程

**角色**：导演，审完发现某镜头要改。

```
你：S1C008 配音不对，要返修
它：S1C008 状态变更：
    - 进度：上色 → 返修中
    - 镜头描述追加：「[5-10 返修] 配音不对」
    私信通知了张三（角色原画）和负责配音的李四。要群里同步吗？

你：不用，让他们自己处理
它：好。返修期间这条会单独标。完成后告诉我，再让我把进度推回原线。
```

**关键能力**：返修不是简单写文字，会改 Stage 字段 + 写备注 + 通知关键负责人；流程自洽。

## 场景 5：项目结项 + 下一部启动

**角色**：制片人，《海岸线》收尾，下一部《雪原》启动。

```
你：海岸线做完了，要开新项目叫《雪原》
它：开新项目前问几个：
    1. 老数据要保留吧？（我会归档到当前 base 的另一张表）
    2. 团队沿用吗？
    3. 老表里还有 2 张未结束的镜头（S2C018、S2C023），怎么处理？

你：保留，团队沿用，那 2 张搬到新项目
它：【计划】
    - 把当前主表 "海岸线" 复制为 "海岸线 · 归档 2026-05-10"
    - 主表清空（保留字段、视图、自动化）
    - S2C018、S2C023 两张挪到清空后的主表
    - 主表改名为《雪原》
    - 团队配置表沿用
    回「确认」执行。

你：确认
它：（执行 → 回执）
    搞定。归档了 58 张镜头到"海岸线 · 归档"，《雪原》主表现在有 2 张待办。
    DDL 还没设，方便说一下吗？
```

**关键能力**：项目级生命周期、归档不丢数据、保留团队、循序渐进问 DDL。

## 场景 6：发现 base 被改动了（自定义吸收）

**角色**：制片人，自己在飞书表里加了个字段，没告诉智能体。

```
你：S1C005 那个"配音状态"现在是已完成
它：等等——我看了一下表，多了一个字段「配音状态」（单选，选项有 已完成 / 进行中 / 未开始）。
    猜可能是用来跟踪每个镜头配音录制阶段？
    方便说一下具体用途吗？

你：对，就是配音录制完没。和上色平行，不影响主进度
它：懂了，已记下：「配音状态」= 配音录制阶段，与上色并行，不影响主 Stage 进度。
    下次扫描就当固有字段处理。
    现在把 S1C005 的配音状态改成"已完成"。

你：嗯
它：已改。
```

**关键能力**：自定义识别（先猜后问再回写）、不替用户做决定、增量学习。

## 场景 7：加新功能 + 万一不合适回滚

**角色**：制片人，想要每周一自动发周报。

```
你：加个每周一早 9 点自动发周报的功能
它：【新功能计划】每周一周报
    目标：每周一 9:00 自动私信项目负责人本周更新汇总
    要改：在 base 加一个 cron 自动化，复用现有的 wkfw1UINiG9ZXf8q 模式
    用户能感觉到的：周一上班看到一条飞书私信，含上周完成镜头清单 + 本周关键节点
    影响：和现有 13 个自动化不冲突
    怎么测：先临时设 5 分钟后触发，看格式
    回滚成本：易（删一个自动化）
    要这样做吗？

你：可以，先测一下
它：（5 分钟后）测试出来了：
    【上周更新】2026-05-03 ~ 2026-05-10
    完成镜头：12 张（S=2 / A=4 / B=5 / C=1）
    本周关键节点：S1C008 角色原画截止 5/13
    试用看看，满意回「保留」，不行回「回滚」。

你：周报别带 emoji
它：好，去掉了。重发一份。
    【上周更新】2026-05-03 ~ 2026-05-10
    完成镜头：12 张（S=2 / A=4 / B=5 / C=1）
    本周关键节点：S1C008 角色原画截止 5/13

你：保留
它：归档了。每周一 9:00 自动跑。要改时间或内容随时说。
```

**关键能力**：Plan→Write→Test→Confirm 流程、试用阶段可调整、最终保留 / 回滚自由。

## 场景 8：误操作恢复

**角色**：制片人，昨天让智能体批量改了一波排期，今天发现改错了。

```
你：昨天那波改排期的能撤回吗？
它：找到 .history/ 里 2026-05-09 的备份：
    - SKILL.md.bak.20260509-153022
    - undo_20260509-153022-batch_reschedule.json
    包含 24 条记录的排期变更。
    回「回滚」我就按这个反向跑一遍。

你：回滚
它：（执行 → 回执）
    已恢复 24 条记录到 5/9 改之前的状态。
    备份还留着，要重新启用直接说。
```

**关键能力**：备份永不丢、跨会话回滚、人话定位（"昨天那波"）不让用户记 txnId。
